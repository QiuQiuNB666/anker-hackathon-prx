02

参赛只有三步

官方原话：「完整参赛流程很简单：先报名，最后提交预赛文档。」但中间这一步最容易掉队。

STEP 1 · 已完成

每人单独报名

报名不筛人，人人可报。注意是「每人」——队伍里每个成员都要自己交一份报名表。

STEP 2 · 已完成

完成组队

PRX 4 人已线下组齐，赛道智能录音。不走招募大厅——官方红字写明「最终队伍信息以提交预赛的队伍信息为准」，大厅只是给找不到队友的人用的撮合平台。

STEP 3 · 你在这里

提交预赛材料

用官方模板写方案，填提交表单并附文档链接。每队仅能提交一次。

❗ 官方明确警告：仅提交报名表、或仅提交预赛材料，都不构成完赛资格。必须完成组队并提交预赛文档才能进入评审。系统会在提交时校验全部队员是否都在已报名池内——有一个人没报名，整队交不上去。
03

四条赛道

每队只能选一条，提交后锁定，原则上不可更换。四条都不是虚构命题，用的是安克在售产品的真实 SDK 和硬件。

TRACK 01

智能录音

把一次「听见」，变成一次真正的理解
硬件底座　录音豆 / soundcore Work 3200 + 移动端 SDK

做一个手机端应用，结合设备的录音、重点标记、状态信息能力。可以改造设备形态、加外设、嵌入自制装置。场景举例：采访、陪护、维修、训练、桌游、调研。要求不止于转写，要能理解、联动、反馈、推进流程。

TRACK 02

智能安防

把一段画面变成一句安心
硬件底座　Anker eufy 摄像头 + 官方 SDK

调用官方 SDK 重新定义一款 App，或从设备本体延展，把它放进一个具体的人、空间、任务里。核心是让画面产生「安心」这种可感知的结果，而不只是录像。

TRACK 03

充电储能

让 AI 决定每一度电怎么用
硬件底座　Anker SOLIX 阳台光储 + 开源 Home Assistant 插件

在 Home Assistant 里做一个「家庭能源大脑」，用插件的实时功率、电池状态、控制写入能力，接入电价与天气信号。场景：光伏自用、动态电价套利、阶梯档位控制、停电备电。要能预测、决策、执行并解释。

TRACK 04

智能服务

真正听懂，真正解决
硬件底座　纯软件：LLM + 多模态 + 知识库检索

做面向真实售后场景的客服 Agent 加高交互前端。要处理情绪识别、产品消歧（「S1 Pro 不吸了」是吸奶器还是扫地机）、故障定位、排障引导、升级处理。四条里唯一不依赖硬件的赛道。

04

预赛：交什么，怎么写，怎么评

预赛是纯文档评审，不需要写代码。9月28–30日评审，从全部报名队伍里筛出 30 支。

提交清单

队名
队伍名称
赛道
四选一，提交后锁定
队长
姓名 + 邮箱 + 手机号，唯一官方联系人
队员
1–3 人，各自姓名 + 邮箱 + 手机号，用于校验报名
方案
按官方模板撰写，提交文档链接
身份校验：队长与队员均以「姓名 + 邮箱 + 手机号」作为唯一身份识别。三者要和报名表完全一致，否则校验不过。

评审五维度（权重制）

选题明确度是否抓住赛道真实业务场景的核心矛盾，而非泛泛而谈
方案清晰度2–3 个核心功能点说清「做什么、怎么做、为什么这样做」
项目创新性是否体现 AI Native 思维，而非套用现有方案
落地可行性24 小时内能否做出可演示原型，是否务实
团队能力技能组合能否支撑方案实现

注意「落地可行性」这一条：评委是拿 24 小时的决赛时长在倒推你的方案，写太大反而扣分。

官方模板的骨架

模板可一键创建副本。官方明说「并非统一格式要求」，欢迎融入团队风格——但三个模块必须都在。

模块一预赛信息卡必须包含

队名 · 意向赛道 · 一句话摘要 · 队长信息（姓名/邮箱/手机号）· 成员介绍与分工（2–4 人含队长，每人的姓名、邮箱、负责工作）

模块二方案成果展示必须包含

正文主体，四个小节：

赛题理解1–2 句说清对命题的理解 + 目标用户是谁、什么特征。官方原话「不需要长篇大论」。
具体方案说明（突出 AI 能力）标记为「非常重要」。展开 2–3 个核心功能点，每个说清「做什么 / 怎么做」，并建议配流程图、页面示意图、原型图或功能结构图。
方案价值与预期效果落地后带来的价值，可测算节省的时间成本与效率提升。并说明 24 小时内能做出什么样的可演示原型。
方案优势 / 创新点几句话：覆盖范围、AI 能力的创新用法、与现有方案的差异化、量化价值估算。
模块三自由展示区可选 · 加分项

技术架构草图、迭代规划、相关项目经历、获奖证明、成员详细介绍。形式不限。评审维度「团队能力匹配」里写着「参考过往作品链接（选填但强烈建议）」——这一栏值得填。

⚠ 提交前必做：模板里单独提示——提交预赛方案文档前，务必开启「互联网获取链接可阅读权限」。评审打不开你的文档，等同于没交。
官方给的减负说明：预赛阶段以轻量化为主，核心内容（赛题理解 + 解决方案）建议控制在精炼篇幅，不要求 Demo、代码、完整立项文档或架构说明。重点是让评审快速理解你们要做什么、为什么做、怎么做。

容易踩的坑

以下每一条都是细则或 FAQ 里写死的硬规则，不是建议。

01
队员漏报名 → 整队无法提交系统在预赛提交时校验全部队员是否在已报名池内。你自己已报名不代表队友报了。组队后第一件事是逐个确认。
02
未报名就开团，队伍会被自动取消组队大厅里已经出现两条「系统拦截·未报名，开团自动取消」的记录。先报名，再开团。
03
赛道提交后锁定每队限选一个赛道，交了原则上不可换。建议看完 9月9日 的赛题解析直播再定。
04
每人限一队不能脚踏两条船，谨慎确认后再提交。
05
每队仅能提交一次预赛不可重复提交，要改只能在截止前联系主办方。
06
提交后不可换队员原则上不可更换，特殊情况需联系主办方。
07
知识产权：方案归你，但摘要授权公开提交即视为授权主办方在宣传中使用队名和方案摘要。涉及商业机密必须提前标注——未标注的，主办方不承担保密义务。
08
入围后 48 小时内必须确认队长在「选手中心 - 我的赛事信息 - 参赛状态」确认，逾期视为放弃，由候补替补。
09
预赛文档忘开公开阅读权限提交的是文档链接不是附件。模板里专门提示要开启「互联网获取链接可阅读权限」——评审点不开，等同于没交。
