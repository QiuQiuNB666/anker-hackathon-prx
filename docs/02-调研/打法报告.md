## 一、格局判断

### 已经是红海的（做了就是送分给别人）

**会议纪要 / 转写 / 摘要 / 待办生成**——这条路不仅被做过，还被做成盈利标杆：
- Plaud 出货 200 万台以上，软件 ARR 破 $100M，约 50% 硬件买家转付费（TechCrunch 2026-06-16）；2025 年年化 $250M 且已盈利、未拿风投（Forbes 2025-09）。你在 24 小时内做不出比它更好的纪要，评委也知道。
- **你手上这颗豆子的官方 App 本身就是这条路**：安克×飞书「AI 录音豆」899 元，2026-01-19 上市，飞书提供声纹识别、实时转写翻译、AI 纪要、飞书知识问答（量子位 2026-01-19）。你做会议场景 = 在飞书主场跟飞书比，且拿不到飞书后端。
- 同一年钉钉 DingTalk A1（499/799 元，72 语种，5 麦+骨传导，IT之家）、讯飞 WAIC 2025 一次发 5 款录音笔（中新网 2025-07-29）。两大办公生态 + 全价位在位者已经把这块占死。
- 底部还有华强北白牌 AI 录音卡 120–150 元（时代周报），"卡片形态 + 多语言转写 + 摘要"这个组合已经是 120 块钱的东西。

**结论：任何以"转写质量 / 形态创新 / 订阅商业模式"为卖点的方案，在预赛"项目创新性"维度上拿不到分。**订阅制这条也别讲——Bee 被亚马逊收购后 $19/月直接取消，$49.99 买断（第三方评测 2026-08）。

### 已被公开验证失败的具体做法（不要重复）

| 做法 | 证据 |
|---|---|
| 独立 always-on 录音吊坠当一门生意 | Limitless 累计仅 2 万台，2025-12-05 卖身 Meta，硬件停售、中国大陆等 7 地区直接停服（CNBC / 36kr）；Humane AI Pin $116M 卖 HP，2025-02-28 集体变砖（ghacks）；Friend 卖出约 3000 台、发货约 1000 台、收入不到 $40 万，死因是"挂胸前根本听不清"+ 7–10 秒延迟（Fortune 2025-10-03） |
| 挂床边/工作台让 AI 总结一天 | HowToGeek 给 soundcore Work 7/10，明确指出**非结构化漫谈对话的摘要没什么用**，只在正式会议/就医记录这类有结构的场景才显著变好 |
| 全程录音全程转写 | 爱搞机实测直接写"对于普通用户肯定是不值得购买的"，两个硬伤：所有录音都强制触发转写、误操作也吃额度、用户无法手动控制（igao7） |
| 纯云端依赖 | 搜狗全线硬件 2024-05-30 停服，AI 录音笔变砖、数据删除（新浪财经 3·15 专题）。这是中国用户对云端 AI 录音硬件最深的不信任 |
| 宠物声音翻译 | Traini（CES 2025，$750 万融资）、Mibuddy（宣称 85%）、PettiChat（宣称 94.6%，早鸟 $119，超 1 万预订）已经拥挤，且第三方评论直指准确率宣称**无法验证**——而决赛明写要求"可验证"。**这个方向会输，别碰。** |

### 真正的空白（也是评委在等的东西）

1. **非语音声学事件**。所有在位者都在做"听人说话"。机器异响、呼吸咳嗽、水流、撞击、动物声——没有任何一家消费级录音设备在做。
2. **执行层**。行业公认的最大未解问题不是"录不准"，是"录完没人看"——原文观点：转写只是原材料，不提炼的原材料不是知识，是库存（mindly-ai，注意这是知识管理公司的立场文，作为观点用）。**赛题原文"不止于转写，而能进一步完成理解、联动、反馈与流程推进"就是照着这个痛点写的。**
3. **用外部信号锚定说话人身份**。说话人分离在会议场景 DER 普遍 10–20%（pyannote 3.1 在 AMI 约 19%），是纯算法解不掉的天花板。用"谁按了按钮 / 设备贴在哪 / 工单里是谁"来锚定，正是赛题"连接环境信息"的字面要求。
4. **稀疏触发架构**。只把 1% 有价值的片段升级为云端完整理解——一句话同时回答成本、隐私、续航、以及"为什么不是只做个更好的纪要"四个问题。
5. **把设备赶出办公室**。赛题举的三个例子（床边、工作台、宠物项圈）全是家庭/现场，而 soundcore Work 的官方定位是会议访谈商务。主办方在用举例明说：把这台 B 端办公设备带去它不该去的地方。

### 你必须知道的硬约束（决定哪些点子物理上不成立）

- **麦克风只有 2 颗 MEMS，5 米拾音**（官方页 + 52audio 拆解）。声源定位、方向判断、左右分离——硬件上做不到。
- **一次只接受一个 BLE 连接**：官方 App 连着的时候你的 App 连不上，反之亦然（andrewseago README 原文 / Shawn-TKD 已知限制）。**"我的 App 做联动、官方 App 做转写"这类方案直接死。**（注意：这是设备端限制，你的手机同时连打印机/ESP32 没问题。）
- **不支持 USB 导出音频**（官方页）。所有音频只能走 BLE / SPP / Wi-Fi SoftAP 三条协议通道。
- **官方 SDK 是存在的**：github.com/AnkerInnovations/SoundcoreSDKDemo（iOS + Android To-B Demo，含 SDK 二进制）。公开的能力清单只有六组：扫描连接 / 录音与文件传输（离线文件列表、蓝牙传输、WiFi 传输、删除）/ 设备控制（重置、同步时间、FindMy）/ 绑定 / OTA / 设备日志。**里面既没有实时音频流，也没有重点标记事件。**
- **"重点标记"是最大未知项**。官方产品页确认双击标记存在（带震动反馈），但社区逆向协议文档和官方 SDK README 两个独立来源都不含 mark 事件。它到底是实时回调、还是写进文件元数据、还是走云侧——完全未知。**任何方案都必须为这两种情况各准备一条路径。**
- iOS 没有 Web Bluetooth（Shawn-TKD README），网页方案在 iPhone 上必死。
- 本体 10g / 直径 23.2mm / IPX4 / 8 小时（48g、60×60×14.95mm 是**充电盒**，别引用错，现场会被拆穿）。
- 免费额度 300 分钟/月，转写全部在云端。

> 关于赛题四个动词的拆解、五维度名称、24 小时/6 分钟赛制：调研中标为 **UNVERIFIABLE**（公开渠道查不到赛题原文与评分表）。以下全部以你提供的报名材料为准，正式动笔前请拿主办方文件逐字比对。

## 二、三个候选方向

自查阈值：一个方案要过关，必须能回答这句反问——**把录音豆换成手机自带麦克风，你的 demo 还成立吗？** 成立 = 自认硬件不可替代性为零，"技术实现"维直接塌。

---

### 方向一（稳妥）：《口述即工单》——师傅的搭档

**一句话**：师傅双手插在机器里，嘴上说的每一句自动填进结构化工单，双击一次 = 推进一道工序，收工时打印机吐出一张纸质工单。

**场景与用户**：家电/电梯/产线设备的上门维修与巡检工程师。真实痛点可量化：维修动作和记录动作强制串行——师傅必须放下工具、脱手套、掏手机、打字。行业里"回车上补工单"是常态，导致记录失真、返修追溯不到。

**核心功能**
1. **槽位化理解，不是摘要**。预置工单模板（设备号 / 故障现象 / 处置动作 / 更换件 / 结论），LLM 只做"把这段话填进哪个槽位"，不做自由摘要。这是绕开"非结构化对话摘要没用"（HowToGeek 已验证）的唯一办法：给 LLM 结构约束。
2. **双击 = 免手确认键**（这一步做完了）。系统语音播报下一步 SOP。把书签反转成流程状态机的推进键。
3. **第二数据源 = 设备身份**。工位上贴 NFC 标签/二维码，手机碰一下确定"这是哪台机器"，录音自动挂到该资产的历史记录上。这是"连接环境信息"的最低成本实现。
4. **物理落地**：58mm 蓝牙热敏打印机（100–150 元，手机直接 ESC/POS，无需 MCU）吐出工单，客户签字。

**24 小时能演示出的**：一台"故障设备"（准备一个能人为制造异响的小风扇/减速机），碰 NFC → 说三句话 → 双击三次 → 屏幕上工单逐格填满 → 打印机吐纸 → 撕下来交给评委。

**打中五维的逻辑**：选题明确（一个人、一个时刻、一个坏结果）；SDK 覆盖最全（录音 + 重点标记 + 状态信息 + 形态改造），"技术实现"维分最好拿；有纸质实物出场，"路演表现"稳；工单是可验证输出，正面回应"可感知可验证"。

**最大风险**：**创新性偏低。**语音填单讯飞和各家 CRM 都有。它靠的是"双击当状态机推进键"和"稀疏触发省额度"两个巧思撑创新分，撑不满。

### 方向二（进攻，**推荐**）：《听诊器》——让录音豆去听机器，不听人

**一句话**：把这颗为人声调音的录音豆磁吸到设备外壳上，让它学会一台机器"健康时的声音"，异响出现时立刻断电/报警/开工单——设备不再录音，它在诊断。

**场景与用户**：小微制造/维修车间/共享设备运营方的日常巡检。空压机、减速机、电机、水泵、洗衣设备。真实结构：99% 无事发生，价值全在那 1%，且人耳听得出但没人 24 小时守着。

**核心功能**
1. **30 秒示教，即刻可用**。不训练模型。录 30 秒"正常声"建立频谱基线（MFCC / 梅尔谱模板），实时比对马氏距离，超阈值即触发。24 小时内完全做得出，且**评委当场可以让你换一台没见过的机器现学现用**——这是最强的可验证性演示。
2. **双击 = 打标签**。师傅听到异常但系统没报，双击一次，这一段被标为"这就是异常"，加进模板库；系统误报，双击一次标为"这正常"。**这是重点标记最漂亮的用法：它不是书签，是在线学习的标注按钮。**
3. **物理执行层**。异响 → 智能插座断电（涂鸦/米家云 API，10 分钟接完，零硬件）或继电器切断 + 灯条变红 + 手机推送给不在现场的老板。
4. **第二数据源**：一个 20 块的 ESP32 + 振动/温度传感器贴在同一台机器上。声学 + 振动交叉确认 → 大幅降低误报。这条同时满足"连接环境信息"和"增加外设"。

**24 小时能演示出的**：现场一台小风扇/搅拌机。① 30 秒学习正常声。② 评委席可以看见电流表/灯是绿的。③ 你伸手往扇叶里塞一张卡纸 → 3 秒内灯变红 + 智能插座啪一声断电 + 手机弹通知 + 打印/写入一条异常记录。**"啪"一声是整场路演最贵的 0.5 秒。**

**打中五维**
- 创新性：彻底跳出 ASR 红海。没有任何一家在位者（Plaud/飞书/钉钉/讯飞/白牌）在做非语音声学。
- 技术实现：形态改造（磁吸贴机器）+ 录音 + 状态信息 + 重点标记 + 外挂传感器，五项全用上，且"为什么必须是这颗豆子"有唯一答案——10g / 23.2mm / 磁吸 / IPX4 / 8 小时，你能把它贴到手机贴不上去的地方（电机侧面、管道背面、床帘后面）。
- 落地可行性：不训练模型、不打板、不接第三方系统。
- 场景价值：预测性维护是有真实付费方的成熟品类。
- 路演：物理断电，评委不需要想象。
- **额外的安克战略分**：阳萌公开主张"未来的大模型应该部署在用户的设备上，而不是云端"（腾讯云开发者社区），Anker Day 2026 发布 Thus™ A1 存算一体音频芯片（30M → 5G FLOPS，约 150 倍，搜狐）。你的方案主链路是**端侧频谱比对、不上云、可开飞行模式跑**，一句话就正中公司战略。

**最大风险（两条，必须提前 derisk）**
1. **拿不到原始音频，只能拿 Opus 有损压缩后的文件**，且设备为人声做的降噪/AGC 可能把机器的稳态频谱吃掉。**这是这个方向的生死线，必须在 9 月内实测**：录一段风扇声，从设备拉出来看频谱是否还能区分。若被破坏严重，退路是改用"瞬态事件"（撞击、摩擦、尖啸）而非稳态频谱——瞬态特征抗压缩得多。
2. 实时性。官方 SDK 不给实时流。**主链路必须设计成"分段拉取"**：短周期启停录音 → Wi-Fi SoftAP 快传 → 分析（约 5–15 秒一轮）。demo 里明确说"3 秒内响应"你做不到，说"10 秒内"你能做到且没人挑剔——工业场景 10 秒完全可接受。**别承诺秒级。**

### 方向三（高风险高回报）：《离线的耳朵》——逆向实时流 + 全端侧 + 飞行模式

**一句话**：绕开官方云管线，直接从设备拉实时音频流，手机端跑端侧模型完成理解与触发，整场演示手机开飞行模式。

**技术依据**：社区逆向文档记录 `0x1A / 0x07 startTransportAudioFile` 的 payload 第 9 字节 `realtimeFlag == 1` 即实时流（tacshi/Soundcore PROTOCOL.md，已逐行核到）。加密链路 ECDH P-256 → HKDF-SHA256 → AES-256-CTR，文件密钥明文前 14 字节固定为 ASCII `soundcored3200`。已有四个独立第三方实现跑通。

**为什么诱人**：技术炫技 + 正中阳萌端侧战略 + 隐私叙事 + 回应搜狗变砖的国民级不信任，四发子弹一次打完。飞行模式跑通全链路在路演现场的冲击力极强。

**为什么大概率输**
- **协议支持 ≠ SDK 透出**。官方 SDK 公开清单里根本没有实时流；决赛你手上的是主办方发的带 license 的 SDK，绕过它用逆向协议，评审席上坐着安克工程师，这是政治问题不只是技术问题。
- **代码不可复用**：tacshi 无 license（法律上保留全部权利，只能读来理解协议，不能抄）；andrewseago 是 GPL-3.0，mic-rs 是 AGPL-3.0，两个传染性协议；只有 Shawn-TKD/recording-bean-web 是 MIT 可用，但它是 Web Bluetooth，iPhone 上不能跑。
- 端侧 ASR（whisper.cpp / sherpa-onnx）在 24 小时里调通 + 调准，是个人赌运气的事。

**建议**：**不要作为主方向。**把"端侧可行性"降级成方向二里的一段话和一个 30 秒的飞行模式演示——用最低成本吃掉这个方向 80% 的战略分。

---

### 推荐：**方向二（听诊器）**，用方向一做保底

理由三条：
1. **红海规避最彻底**。TreeHacks 2026 总冠军 Shepherd 是一根 $40–60 的电动化盲杖，不是一个新设备（GitHub tonywangs/shepherd + Stanford Daily 双源确认）。AdventureX 2025 硬件赛道第一 Echozen 是"脑电 → AI → 机械臂推水杯"（宁诺官方新闻稿）。深圳女性硬件黑客松最高奖是一副经痛疗愈耳机（星岛）。**获奖姿势高度一致：改造一个已有器物 + 打中一个被忽视的场景 + 一个当场看得见的物理动作。**方向二三条全中。
2. **"为什么必须是这颗豆子"有唯一答案**，方向一没有（手机放桌上也能录师傅说话）。
3. 决赛"完成度=是否兑现预赛承诺"这一维里，示教式模板匹配的承诺是最容易 100% 兑现的——因为不涉及任何模型训练。

**风险对冲的正确姿势**：预赛文档里两条链路都写（口述工单是同一套架构的第二应用），但**只把听诊器写进承诺清单**，工单那条用一句"同一套感知-理解-执行架构可迁移至……"带过。这是 24 小时黑客松的铁律——AngelHack 复盘原话：赢家挑一个能做完的问题，而不是他们想解决的问题。

### 如果队里没有硬件人（分支）

方向二**完全可以零焊接完成**：
- 执行器：涂鸦 / 米家智能插座（云 API，App 直调）+ 一个台灯。断电和亮灯的视觉效果和继电器一模一样。
- 第二数据源：手机 IMU（把手机绑在机器上当振动传感器）+ 时间/位置。免了 ESP32。
- 结构件：磁吸片 + 3M 胶 + 亚克力/纸板托架，30 分钟搞定。
- 打印机：蓝牙热敏打印机是即插即用外设，不算硬件工作。

**有硬件人时才升级**：ESP32 + ADXL345 振动传感器 + 继电器模块 + 3D 打印磁吸托架（对标 MIT Reality Hack 最佳硬件 Tac-Man 的配方：3D 打印件 + 3 个舵机 + ESP32 + 无线通信）。**不要做任何需要打板、注塑、新电池管理的东西**——Humane 死于发热和电池这类物理问题，24 小时现场最容易暴露。**绝对不要试图从豆子取电**（本体电池仅 90mAh）。

## 三、演示设计（6 分钟 + 3 分钟）

先立一条原则：**Demo-Driven Development**——先把这 6 分钟逐秒写死，再倒推实现，脚本外的功能一律不做。TreeHacks 参赛者复盘原话是"评委不会看你的代码，但一定会看你的落地页、demo 视频和 pitch"（sestech.substack.com）。Cal Hacks 12.0 冠军的做法更狠：为了演示稳定，**直接砍掉 agent 的点击能力只留键盘**（blog.dylanlu.com）。你也要准备好砍。

### 分镜

**0:00–0:30｜不讲技术，讲一个数字和一个人**
桌上摆一台正在转的机器（保持开机、有声音，从第一秒就在响）。
> "这是一台空压机。它坏之前会先响三天。这三天没有人在听。"
（一句话说清：谁、什么时刻、什么坏结果。不要放团队介绍页，不要放技术架构图。）

**0:30–1:30｜说清为什么这颗豆子必须在场**
- 一句话点掉红海：会议纪要飞书和钉钉已经做完了，我们没做转写。
- 亮硬件：把 10g 的豆子从手心里拿出来，"啪"一下磁吸到机器外壳上。**这个动作本身就是"设备改造"的最好证明，比任何一页 PPT 都强。**
- 一句话说清架构：**声音进来，只有 1% 会离开这台手机。**

**1:30–2:30｜现场示教（第一个真实动作）**
点"学习" → 30 秒倒计时 → 屏幕上出现这台机器的声纹基线。
> "它现在认识这台机器了。整个过程没有联网、没有训练、没有标注。"
**这里开飞行模式**，屏幕右上角飞行模式图标全程留在画面里。

**2:30–3:30｜制造故障（全场最关键的 60 秒）**
往扇叶里塞卡纸 / 拧松一个螺丝 / 用扳手卡一下齿轮。
→ 手机振动 + 灯条变红 + **智能插座"啪"一声断电，机器停转**。
→ 屏幕上出现异常时刻的频谱切片 + 一条工单。
**留 3 秒静默让评委听见机器停下来的安静。**不要在这 3 秒里说话。

**3:30–4:15｜重点标记的反转用法（第二个真实动作）**
让一位评委在旁边说话/拍桌子，系统误报一次。
→ 你伸手**双击豆子**（豆子震动确认），屏幕上这条被标为"正常，学进去"。
→ 再拍一次桌子，不再报警。
> "这个双击键，官方设计是给录音打书签的。我们把它变成了在线学习的标注按钮——师傅的耳朵比模型准，我们让他一秒钟就能教会它。"
**这一段的作用：证明你不是在演一个写死的脚本。评委最想验证的就是这个。**

**4:15–5:15｜闭环与规模**
- 手机推送到不在现场的班组长（真的推一条，让评委看见另一台手机亮起来）。
- 一句话讲成本与迁移：`30 秒示教 = 一台新设备上线`，一个班组 8 台机器一颗豆子轮巡。
- 一句话讲战略（不超过 15 秒）："今天的比对跑在手机上；产品化时这套特征提取只有几百 KB，可以下沉到 Thus 这一代音频芯片上。"

**5:15–6:00｜收口**
回到第一句话："这三天，现在有人在听了。"
最后一屏放：**已实现 / 未实现**两栏清单。主动列出你没做的东西（多设备、长期数据、云端看板）。这一屏在"完成度"和诚信上的收益远大于多吹一个功能。

### 3 分钟问答：五个必被问的，和标准答案

**Q1：为什么不用手机麦克风就行了？**
> 三点。① 位置：手机不能磁吸在电机侧面、管道背面、床帘后面，豆子 10g、23.2mm、IPX4 可以。② 手机得干别的：它要跑分析、要推送、要接插座。③ 一个班组一颗豆子 899 元轮巡 8 台设备，成本结构和"每台设备装一部手机"不是一回事。
（这题答不好，整个方案的硬件必要性归零。背熟。）

**Q2：你用了哪些 SDK 能力？**
> 扫描与连接、设备绑定、录音启停、离线文件列表与 Wi-Fi 快传、电量与充电状态推送、重点标记。其中重点标记不是当书签用，是当在线标注按钮用；状态信息不是显示在 UI 上，是拿来做"设备是否还在岗"的看门狗。
（能答出多条能力、且每条都有非默认用法，"技术实现"维直接拉开身位。**如果实测下来标记事件拿不到实时回调，改口径为"标记写入文件元数据，传输后回读"，事先把两套话都练好。**）

**Q3：误报率多少？会不会一直响？**
> 不给百分比——现场刚学 30 秒的模型给准确率是不诚实的。给机制：阈值 + 迟滞 + 冷却窗口三个旋钮，加上双击一秒钟纠正。产品化的验证方法是 A/B 双机对照跑两周。
（**永远不要编准确率数字。**这个品类已经因为不可验证的准确率宣称被公开批评过——PettiChat 宣称 94.6%、Mibuddy 宣称 85%，第三方评测直指无法验证。你说"我不知道，但我有纠错机制"比说 95% 得分高。）

**Q4：隐私？它一直在听。**
> ① 主链路端侧、飞行模式下跑通，刚才你们看见了。② 只有触发后的 10 秒片段会离开本机，且用户可关。③ 我们不拿任何音频训练模型。
> 补一句硬的：2026 年 8 月 13 日，加州北区法院在 Otter.ai 集体诉讼里部分驳回了 Otter 的驳回动议，认定原告已合理主张 Otter 属"第三方窃听者"而非中立工具——关键理由正是它保留对话用于训练自己的模型。所以我们从架构上就不碰这条线。
（有具体判例的隐私回答，杀伤力比任何口号大十倍。）

**Q5：这跟一个 200 块的工业振动传感器有什么区别？**
> 振动传感器要贴在轴承座上、要接线、要标定，一台机器一个。声音是唯一能隔空、免接触、一对多采集的信号，人耳几十年来就是这么判断的。我们做的是把师傅的耳朵复制一份，不是加一个仪表。
（这题会被工程背景的评委问。必须有答案。）

### 三层兜底（AngelHack 建议：提交前 4 小时锁代码、live demo 至少走查 5 遍、demo 视频录两遍）

| 失效点 | 兜底 |
|---|---|
| 网络断（几十支队伍抢 Wi-Fi） | 主链路本来就是端侧，无影响；云端 LLM 生成的工单文案改用本地模板 |
| SDK / BLE 连不上真机 | 立即切换到手机麦克风采集，下游管线完全不变，一个开关 |

| 整机翻车 | 提前录好两遍 demo 视频，本地播放，不依赖任何网络 |

**特别注意**：Wi-Fi SoftAP 快传期间手机会切到设备热点、断开互联网。演示流程里**绝不能出现"快传的同时调云端 LLM"**，这个切换一定卡住。

## 五、预赛文档写法

先说结论：**大多数队伍会写砸的是"落地可行性"，而这是最容易靠格式拿满分的一维。**评委在没见到人、没见到 demo 的情况下，只能靠文档结构判断你会不会在决赛翻车。Devpost 采访的资深评委明确说，最伤分的是"在某一项标准上过度投入而损害了提交的其余部分"（Square 的 Richard Moot 原话），以及"惊讶于有多少提交根本不满足赛题基本要求"（Databricks 的 Karen Bajza-Terlouw）。

### 逐维度

**① 选题明确度（1 页，最先写，最难写）**
- 开头必须是一句话，含三个要素：**谁 + 在什么时刻 + 什么具体的坏结果**。
  > "小微车间的设备管理员，在设备开始异响到彻底停机之间的 3 天里，没有任何人在听。"
- 紧跟一个可量化的现状（哪怕是你自己做的 5 个用户访谈的数字，注明样本量）。**做 5 个真实访谈，比引用任何行业报告都值钱**，而且能在决赛问答里当弹药。
- 用**一整段明确写出你不做什么**："我们不做会议纪要、不做转写摘要、不做多语言翻译。"主动划边界是选题明确度的最强信号。

**② 方案清晰度（1.5 页，靠图不靠字）**
- 核心是**一张端到端数据流图**：麦克风 → 分段拉取 → 特征提取（端侧）→ 模板比对 → 决策 → 执行器/推送 → 反馈回设备。每个框标清"在哪跑"（设备/手机端侧/云）。
- 用赛题原文的动词做小标题逐条自证（**注：调研中"四个动词"的拆解标为 UNVERIFIABLE，请按主办方赛题原文的实际用词来定小标题**）。让评委不需要自己去找你是否命中了赛题要求。
- **写明每条链路走的是哪个 SDK 接口**。这是你相对于所有队伍的最大信息优势——官方 SoundcoreSDKDemo 是公开仓库，你可以直接写出真实的初始化参数（`SDKInitConfig`：context / userId / deviceId / token / licenseJson / license_signature / environment / commandTimeOut / fileTransferInterval），并写明"license_signature 由服务端签发、修改 licenseJson 会使签名失效，需向主办方申请授权"。**这一段在评委眼里是做过功课的硬证据，绝大多数队伍写不出来。**

**③ 项目创新性（1 页，只讲三个点，讲透）**
不要罗列功能。只讲三个反转：
1. 让为人声设计的录音设备去听机器（品类空白）。
2. 把重点标记从书签反转为在线学习的标注按钮（SDK 能力的非默认用法）。
3. 稀疏触发架构：99% 的声音不上云。**明确写出这一条同时回答成本、隐私、续航三个问题**——并引用设备本身的约束作为论据（免费额度 300 分钟/月、官方转写走云端、爱搞机实测批评"所有录音强制触发转写、误操作也吃额度、用户无法手动控制"）。用官方产品自己的痛点做论据，是最有说服力的创新论证。

**④ 落地可行性（1.5 页，这一维决定初筛，也是大多数队伍写砸的地方）**

大多数队伍在这一维写砸的方式是：整页都在讲"我们会做到 X、Y、Z"，一个具体时间数字都没有。评委无法证伪你的创意，但一眼能看出你有没有算过时间账。

必须有的三样东西：
1. **小时级排期表**（就是第四节那张，直接放进去），含明确的"联调窗口"和"彩排窗口"。
2. **风险与应对表**，主动点名自己会踩的坑：

| 风险 | 概率 | 应对 |
|---|---|---|
| 重点标记无实时事件回调 | 高 | 两条路径：实时回调 / 文件元数据回读，均已预留接口 |
| Opus 压缩 + 人声降噪破坏机器声频谱 | 中 | 已于 9 月实测（附频谱图）；若失效则改用瞬态特征 |
| 现场无可用网络 | 高 | 主链路端侧，飞行模式下可完整运行 |
| SDK license 未到位/真机连不上 | 中 | 手机麦克风采集兜底，下游管线不变 |

3. **明确的不做清单**：不训练模型、不打板、不做账号体系、不做多端、不做历史数据管理、不接第三方业务系统。

**主动示弱比全面吹牛更能拿这一维的分。**

**⑤ 团队能力匹配（0.5 页，最便宜的分）**
- 表格：姓名 / 角色 / 本项目负责模块 / **既往证据**。
- 球球这一行的写法：`架构与 Agent 编排 —— 曾独立交付 FastAPI + ffmpeg 的 AI 视频生产流水线（十余个服务模块）、LLM 网关中转服务`。**具体项目名 + 模块数量，比"5 年后端经验"有力十倍。**
- **必须有一行是"路演"**。AngelHack 的观察：含前端/后端/演讲的均衡三人配置几乎总是胜过全技术队伍。如果 4 个人全是工程师，也要指定一个人的角色写成"路演与用户访谈"。
- 如果队里没有硬件人，**大方写出来**，并写明"因此方案的所有物理外设均采用免焊接的成品模块（智能插座 / 蓝牙热敏打印机 / 磁吸结构件）"。这反而变成落地可行性的加分。

### 全局写作纪律

- **总长度控制在 6–8 页。**功能列表超过 5 条、或文档里出现"平台""生态""操作系统"这三个词，就是在给评委发"这队会翻车"的信号。
- **预赛承诺 = 决赛完成度的评分基准。**你在预赛写下的每一个功能，决赛都要兑现。**把承诺压到 24 小时内 100% 能做完的范围，然后在文档里主动说"我们刻意把 MVP 压到三个功能"**——这句话本身就是加分项。
- 不要写任何"往届获奖案例"。这是安克首届黑客松，**不存在往届**。任何声称往届的内容都是编造。

### 第二周（9/16 – 9/22）：技术穿刺，把生死线实测掉

这一周只有一个目标：**把方向二的两条生死线用真设备验证掉，而不是推理掉。**

1. **【最高优先级】音频通路实测**：设备录一段风扇/电机声 → 用官方 SDK 拉出来 → 解码 → 看频谱。判断标准：正常态和异常态的梅尔谱模板距离是否可分。**这一条不通，方向二当场换方向一，不要拖到 10 月。**

3. **Wi-Fi SoftAP 快传实测**：测一次传输耗时，以及切热点后互联网断开的时长。这决定分段拉取的周期能压到多少秒——决定你路演时敢承诺几秒响应。
4. **智能插座 / 打印机点亮**：半天工作量，先跑通再说。
5. **Walking skeleton**：手机麦克风 → 特征 → 阈值 → 插座断电，端到端跑通一次。**这一步完全不依赖录音豆**，先证明下游管线是通的，10/16 那天只剩"把输入源换成豆子"这一件事。
6. **诊断纪律**：任何连接失败，第一步永远是最底层的健康检查（设备是否被官方 App 占住 BLE 连接？蓝牙权限/位置权限/本地网络权限给了吗？），不要跳过这步猜应用层原因。**同一个操作连续失败 2–3 次就停下来 checkpoint，不要闷头试第 7 次。**
