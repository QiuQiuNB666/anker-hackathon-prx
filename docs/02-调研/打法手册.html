先看硬约束

这批事实来自官方产品页、52audio 拆解、官方 SDK 仓库和社区逆向文档。每一条都能直接杀死一类想法——在动笔写方案之前先过一遍，比任何创意都省时间。

01
一次只接受一个 BLE 连接官方 App 连着的时候你的 App 连不上，反之亦然。「我的 App 做联动、官方 App 做转写」这类方案当场出局。（注意这是设备端限制，手机同时连打印机、ESP32 没问题。）
02
官方 SDK 没有实时音频流，也没有重点标记事件公开能力清单只有六组：扫描连接 / 录音与文件传输 / 设备控制 / 绑定 / OTA / 设备日志。想做实时响应，只能设计成「短周期启停录音 → 分段拉取」，一轮约 5–15 秒。路演别承诺秒级，说「10 秒内」你做得到且没人挑剔。
03
「重点标记」是最大未知项产品页确认双击标记存在（带震动反馈），但社区逆向文档和官方 SDK README 两个独立来源都不含 mark 事件。它是实时回调、还是写进文件元数据、还是走云侧——完全未知。任何方案都要为两种情况各准备一条路径。
04
只有 2 颗 MEMS 麦克风，5 米拾音声源定位、方向判断、左右分离——硬件上做不到，别写进方案。
05
不支持 USB 导出音频所有音频只能走 BLE / SPP / Wi-Fi SoftAP 三条协议通道。而且 SoftAP 快传期间手机会切到设备热点、断开互联网——演示流程里绝不能出现「快传的同时调云端 LLM」，这个切换一定卡住。
06
本体 90mAh 电池，10g / 直径 23.2mm / IPX4 / 8 小时别想从豆子取电驱动外设。另外：48g、60×60×14.95mm 是充电盒的参数，引用错了现场会被拆穿。
07
iOS 没有 Web Bluetooth网页方案在 iPhone 上必死。官方 SDK 同时提供 iOS Framework 和 Android AAR，建议主攻 Android 原生。
08
转写全部走云端，免费额度 300 分钟/月这既是约束也是弹药——爱搞机实测批评它「所有录音强制触发转写、误操作也吃额度、用户无法手动控制」。用官方产品自己的痛点论证你的稀疏触发架构，是最有说服力的创新论证。
官方 SDK 是公开的：github.com/AnkerInnovations/SoundcoreSDKDemo（iOS + Android To-B Demo，含 SDK 二进制）。初始化参数是 SDKInitConfig：context / userId / deviceId / token / licenseJson / license_signature / environment / commandTimeOut / fileTransferInterval。license_signature 由服务端签发，改 licenseJson 会使签名失效，必须向主办方申请授权。在预赛文档里写出这一段，是绝大多数队伍写不出来的硬证据。

红海与真空

已经是红海

做了等于送分
  • 会议纪要 / 转写 / 摘要 / 待办——Plaud 出货 200 万台以上、软件 ARR 破 1 亿美元、约 50% 硬件买家转付费，且未拿风投已盈利。你在 24 小时内做不出比它更好的纪要，评委也知道。
  • 你手上这颗豆子的官方 App 就是这条路。安克 × 飞书「AI 录音豆」899 元，2026-01 上市，飞书提供声纹识别、实时转写翻译、AI 纪要。做会议场景 = 在飞书主场跟飞书比，且拿不到它的后端。
  • 同年钉钉 A1（499/799 元，72 语种）、讯飞 WAIC 2025 一次发 5 款录音笔。两大办公生态 + 全价位在位者已占死。
  • 底部还有华强北白牌 AI 录音卡 120–150 元。「卡片形态 + 多语言转写 + 摘要」已经是 120 块钱的东西。
  • 宠物声音翻译——Traini、Mibuddy、PettiChat 已拥挤，且准确率宣称被第三方指出无法验证，而决赛明写要求「可验证」。这个方向会输。

真空地带

评委在等的东西
  • 非语音声学事件。所有在位者都在做「听人说话」。机器异响、呼吸咳嗽、水流、撞击、动物声——没有任何一家消费级录音设备在做。
  • 执行层。行业最大未解问题不是「录不准」，是「录完没人看」。赛题原文「不止于转写，而能进一步完成理解、联动、反馈与流程推进」就是照着这个痛点写的。
  • 用外部信号锚定说话人身份。说话人分离在会议场景 DER 普遍 10–20%（pyannote 3.1 在 AMI 约 19%），纯算法解不掉。用「谁按了按钮 / 设备贴在哪 / 工单里是谁」锚定，正是赛题「连接环境信息」的字面要求。
  • 稀疏触发架构。只把 1% 有价值的片段升级为云端理解——一句话同时回答成本、隐私、续航，以及「为什么不是只做个更好的纪要」。
  • 把设备赶出办公室。赛题举的三个例子（床边、工作台、宠物项圈）全是家庭与现场，而 soundcore Work 的官方定位是会议访谈商务。主办方在用举例明说：带它去它不该去的地方。
另有五类做法已被公开验证失败，不要重复：独立 always-on 录音吊坠当生意（Limitless 累计仅 2 万台后卖身 Meta、Humane AI Pin 集体变砖、Friend 死于「挂胸前根本听不清」）；让 AI 总结非结构化漫谈（HowToGeek 实测指出对漫谈摘要没什么用）；全程录音全程转写；纯云端依赖（搜狗全线硬件停服变砖，是中国用户对云端 AI 录音硬件最深的不信任）；订阅制（Bee 被亚马逊收购后直接取消月费）。

三个方向

自查阈值：把录音豆换成手机自带麦克风，你的 demo 还成立吗？成立 = 硬件不可替代性为零，「技术实现」维直接塌。

方向一 · 稳妥 · 保底

口述即工单

师傅双手插在机器里，嘴上说的每句话自动填进结构化工单，双击一次推进一道工序，收工时打印机吐出一张纸质工单。
关键设计
槽位化理解，不做自由摘要。预置工单模板，LLM 只判断「这段话填进哪个槽位」——这是绕开「非结构化对话摘要没用」的唯一办法：给 LLM 结构约束。
24h 能演示
碰 NFC 认机器 → 说三句话 → 双击三次 → 工单逐格填满 → 热敏打印机吐纸 → 撕下来交给评委。
最大风险
创新性偏低。语音填单讯飞和各家 CRM 都有。靠「双击当状态机推进键」撑创新分，撑不满。
方向二 · 进攻推荐

听诊器

让录音豆去听机器，不听人。30 秒学会一台机器健康时的声音，异响出现时立刻断电报警——设备不再录音，它在诊断。
关键设计
30 秒示教，不训练模型。录 30 秒正常声建立频谱基线（梅尔谱模板），实时比对马氏距离超阈值即触发。评委当场可以让你换一台没见过的机器现学现用——这是最强的可验证性演示。
标记反转
双击不是打书签，是在线学习的标注按钮。误报时双击标为「正常，学进去」；漏报时双击标为「这就是异常」。SDK 能力的非默认用法。
执行层
异响 → 智能插座断电（涂鸦/米家云 API，零硬件）+ 灯条变红 + 推送给不在现场的班组长。
24h 能演示
30 秒学习 → 往扇叶里塞卡纸 → 3 秒内灯变红 + 插座「啪」一声断电 + 手机弹窗。那声「啪」是整场路演最贵的 0.5 秒。
战略加分
阳萌公开主张「大模型应部署在用户设备上而不是云端」，Anker Day 2026 发布 Thus™ A1 存算一体音频芯片。你的主链路端侧、可开飞行模式跑，一句话正中公司战略。
生死线
必须在 9 月实测：拿到的是 Opus 有损压缩音频，且设备为人声做的降噪/AGC 可能吃掉机器的稳态频谱。录一段风扇声拉出来看频谱是否还可分。若被破坏严重，退路是改用瞬态事件（撞击、摩擦、尖啸）——瞬态特征抗压缩得多。
方向三 · 高风险 · 不建议做主线

离线的耳朵

绕开官方云管线，直接逆向拉实时音频流，端侧跑完整理解，全程飞行模式。
技术依据
社区逆向文档记录 0x1A / 0x07 payload 第 9 字节 realtimeFlag == 1 即实时流，已有四个独立第三方实现跑通。
为什么会输
协议支持 ≠ SDK 透出。决赛你手上是主办方发的带 license 的 SDK，绕过它用逆向协议，评审席上坐着安克工程师——这是政治问题不只是技术问题。
许可证陷阱
tacshi 无 license（保留全部权利，只能读不能抄）；andrewseago 是 GPL-3.0、mic-rs 是 AGPL-3.0（传染性）；只有 该选手-TKD/recording-bean-web 是 MIT 可用，但它是 Web Bluetooth，iPhone 上跑不了。
正确用法
降级成方向二里的一段话 + 30 秒飞行模式演示，用最低成本吃掉这个方向 80% 的战略分。
为什么推荐方向二：获奖姿势高度一致——TreeHacks 2026 总冠军 Shepherd 是一根 40–60 美元的电动化盲杖；AdventureX 2025 硬件赛道第一 Echozen 是「脑电 → AI → 机械臂推水杯」；深圳女性硬件黑客松最高奖是一副经痛疗愈耳机。改造一个已有器物 + 打中一个被忽视的场景 + 一个当场看得见的物理动作，方向二三条全中。而且「为什么必须是这颗豆子」有唯一答案（10g / 23.2mm / 磁吸 / IPX4，能贴到手机贴不上去的地方），方向一没有。
如果队里没有硬件人：方向二完全可以零焊接完成。执行器用涂鸦/米家智能插座（云 API 直调）+ 台灯，视觉效果和继电器一样；第二数据源用手机 IMU 绑在机器上当振动传感器；结构件用磁吸片 + 3M 胶 + 亚克力托架，30 分钟搞定。不要做任何需要打板、注塑、新电池管理的东西——Humane 就死于发热和电池这类物理问题。

路演分镜

原则是 Demo-Driven Development：先把时间逐秒写死，再倒推实现，脚本外的功能一律不做。Cal Hacks 12.0 冠军为了演示稳定，直接砍掉 agent 的点击能力只留键盘。你也要准备好砍。

⚠ 时长待确认：下面按《赛事细则》的 6 分钟演示 + 3 分钟问答排。但 9/9 直播纪要说的是 3 分钟 + 2 分钟。若确认是 3+2，压缩方案是：0:00–0:20 开场一句话 → 0:20–0:50 磁吸上机 + 30 秒示教 → 0:50–1:50 制造故障与断电（这 60 秒一秒不能少） → 1:50–2:30 双击纠错 → 2:30–3:00 收口与已实现/未实现清单。闭环与规模那一段整段砍掉，放进问答里答。
0:00–0:30
不讲技术，讲一个人
桌上摆一台正在转的机器，从第一秒就在响。不要团队介绍页，不要架构图。
这是一台空压机。它坏之前会先响三天。这三天没有人在听。
0:30–1:30
说清为什么这颗豆子必须在场
一句话点掉红海（纪要飞书钉钉做完了，我们没做转写）→ 把 10g 的豆子从手心拿出来「啪」一下磁吸到机器外壳上。这个动作本身就是「设备改造」的最好证明，比任何一页 PPT 都强。
1:30–2:30
现场示教 · 第一个真实动作
点「学习」→ 30 秒倒计时 → 屏幕出现这台机器的声纹基线。这里开飞行模式，图标全程留在画面里。
它现在认识这台机器了。没有联网、没有训练、没有标注。
2:30–3:30
制造故障 · 全场最关键的 60 秒
往扇叶里塞卡纸 → 手机振动 + 灯条变红 + 智能插座「啪」一声断电，机器停转 → 屏幕出现异常时刻的频谱切片和一条工单。留 3 秒静默让评委听见机器停下来的安静。不要在这 3 秒里说话。
3:30–4:15
标记反转 · 第二个真实动作
让评委拍桌子制造一次误报 → 你双击豆子（震动确认）→ 这条被标为「正常，学进去」→ 再拍一次，不再报警。作用是证明你不是在演一个写死的脚本——评委最想验证的就是这个。
4:15–5:15
闭环与规模
真的推一条通知，让评委看见另一台手机亮起来。讲成本：30 秒示教 = 一台新设备上线，一个班组 8 台机器一颗豆子轮巡。战略话术不超过 15 秒。
5:15–6:00
收口
回到第一句话：「这三天，现在有人在听了。」最后一屏放已实现 / 未实现两栏清单，主动列出没做的东西。这一屏在「完成度」和诚信上的收益远大于多吹一个功能。

3 分钟问答：五个必被问的

Q1为什么不用手机麦克风就行了？
三点。① 位置：手机不能磁吸在电机侧面、管道背面、床帘后面，豆子 10g、23.2mm、IPX4 可以。② 手机得干别的：跑分析、推送、接插座。③ 一个班组一颗豆子轮巡 8 台设备，成本结构和「每台设备装一部手机」不是一回事。
这题答不好，整个方案的硬件必要性归零。背熟。
Q2你用了哪些 SDK 能力？
扫描连接、设备绑定、录音启停、离线文件列表与 Wi-Fi 快传、电量与充电状态推送、重点标记。其中重点标记当在线标注按钮用；状态信息拿来做「设备是否还在岗」的看门狗。
能答出多条且每条都有非默认用法，「技术实现」维直接拉开身位。如果实测下来标记拿不到实时回调，改口径为「写入文件元数据，传输后回读」——两套话都要练。
Q3误报率多少？会不会一直响？
不给百分比。给机制：阈值 + 迟滞 + 冷却窗口三个旋钮，加上双击一秒纠正。产品化的验证方法是 A/B 双机对照跑两周。
永远不要编准确率数字。这个品类已经因为不可验证的准确率宣称被公开批评过。说「我不知道，但我有纠错机制」比说 95% 得分高。
Q4隐私？它一直在听。
这题是你的送分题，别只做防守。① 我们不录人——听的是机器，主办方划的「必须被录人知情、禁止偷录窃听」这条红线，我们在架构上就不可能触碰。② 主链路端侧，飞行模式下跑通，刚才你们看见了。③ 只有触发后的 10 秒片段会离开本机，且用户可关。④ 不拿任何音频训练模型。
9/9 命题解析夜把「被录人知情」列为命题核心要求。同赛道另外三支队伍做的都是「听人说话」（销售对话、情绪监测、知识索引），这条对他们是成本，对你是优势——主动说出来，别等评委问。
还可以补一句判例：2026 年 8 月加州北区法院在 Otter.ai 集体诉讼中部分驳回了 Otter 的动议，认定原告已合理主张其属「第三方窃听者」，理由正是保留对话用于训练自有模型。
Q5这跟一个 200 块的工业振动传感器有什么区别？
振动传感器要贴在轴承座上、要接线、要标定，一台机器一个。声音是唯一能隔空、免接触、一对多采集的信号，人耳几十年来就是这么判断的。我们做的是把师傅的耳朵复制一份，不是加一个仪表。
这题会被工程背景的评委问。必须有答案。

24 小时排期骨架

真实可写代码时间约 14–16 小时（扣睡眠、吃饭、联调、录视频、彩排）。角色：A 队长（架构+后端+Agent 编排）｜B 移动端（Android+SDK）｜C 算法信号｜D 硬件结构+路演。没有硬件人则 D 并入 A/B。

时段动作
14:00–15:00冻结。全员白板画死数据流图 + 逐秒写死 6 分钟脚本，脚本外功能全部划掉。定 3 个接口契约。
15:00–17:00A 后端骨架（单文件 FastAPI：/ingest 收片段 → 返回 status/score/action）｜B SDK 初始化+扫描+绑定+录音跑通真机｜C 离线跑通特征提取（读 wav → 梅尔谱 → 模板距离，先不接设备）｜D 结构件做完 + 麦克风距离实测
17:00 关口一B 是否已能从设备拉到一个音频文件？拉不到 → 立即启用手机麦克风兜底，此后不再回头修 SDK。
18:00–20:00A 分段拉取调度器｜B 文件传输（SoftAP 优先，蓝牙兜底）+ 解码 PCM｜C 用真设备录音标定阈值/迟滞/冷却，留可视化调参｜D UI 主页面（学习中/正常/异常三态，只做一页）
21:00–23:00端到端第一次贯通。说话 → 拉文件 → 打分 → 触发插座。这是今晚唯一目标，其它都可以砍。
23:00 关口二贯通了 → 进打磨；没贯通 → 砍 SoftAP 只用蓝牙、砍重点标记、砍推送，留主干。
00:00–03:00重点标记接入（两条路径都试，先成先用）｜在线学习：双击加进模板｜误报调优（开电视、开空调、多人说话实测）｜录 demo 视频第一遍
03:00–07:00轮流睡 4 小时，两两轮换，任何时刻至少 2 人醒着。
07:00–09:00云端 LLM 生成工单文案（可选，做不完就砍）｜UI 收尾 + 飞行模式路径验证｜参数固化为一套「演示参数」｜PPT 不超过 6 页 + 已实现/未实现清单
09:00 冻结代码此后只允许改文案和参数，不允许改逻辑。
10:00–13:00彩排 5 遍，掐表。其中一遍故意断网、一遍故意让插座失败，练兜底话术。11:00 录 demo 视频第二遍。
13:00–14:00问答对练（五个必答题各过两遍）+ 设备充电 + 物料摆位。
三层兜底：网络断 → 主链路本就端侧，云端 LLM 文案改本地模板；SDK 连不上真机 → 一个开关切手机麦克风，下游管线不变；插座云 API 挂 → 灯条 + 手机全屏红 + 音效；整机翻车 → 提前录好的两遍 demo 视频本地播放。两个关口的砍功能决定必须当场做，不许「再试半小时」。
08

预赛文档怎么写

大多数队伍会写砸的是「落地可行性」，而这是最容易靠格式拿满分的一维。评委在没见到人、没见到 demo 的情况下，只能靠文档结构判断你会不会在决赛翻车。总长控制在 6–8 页。

维度怎么写
选题明确度
1 页		开头一句话必须含三要素：谁 + 在什么时刻 + 什么具体的坏结果。紧跟一个可量化现状——做 5 个真实用户访谈，比引用任何行业报告都值钱，且能在决赛问答里当弹药。用一整段明确写「我们不做什么」：不做会议纪要、不做转写摘要、不做多语言翻译。主动划边界是选题明确度的最强信号。
方案清晰度
1.5 页		核心是一张端到端数据流图，每个框标清「在哪跑」（设备/手机端侧/云）。用赛题原文的动词做小标题逐条自证，让评委不用自己找。写明每条链路走哪个 SDK 接口——公开仓库的真实初始化参数和 license 签发机制，是绝大多数队伍写不出来的硬证据。
项目创新性
1 页		不要罗列功能，只讲三个反转讲透：① 让为人声设计的设备去听机器；② 把重点标记从书签反转为在线学习标注按钮；③ 稀疏触发，99% 的声音不上云——这一条同时回答成本、隐私、续航三个问题。
落地可行性
1.5 页 · 决定初筛		写砸的方式是整页讲「我们会做到 X、Y、Z」，一个时间数字都没有。必须有三样：小时级排期表（含联调窗口和彩排窗口）、风险与应对表（主动点名自己会踩的坑）、明确的不做清单（不训练模型、不打板、不做账号体系、不做多端）。主动示弱比全面吹牛更能拿这一维的分。
团队能力
0.5 页 · 最便宜的分		表格：姓名 / 角色 / 负责模块 / 既往证据。队长那行写「架构与 Agent 编排 —— 曾独立交付 FastAPI + ffmpeg 的 AI 视频生产流水线（十余个服务模块）、LLM 网关中转服务」，具体项目 + 模块数量比「5 年后端经验」有力十倍。必须有一行是「路演」——含演讲角色的均衡配置几乎总是胜过全技术队伍。
最重要的一条纪律：预赛承诺 = 决赛「完成度」的评分基准。你写下的每个功能决赛都要兑现。把承诺压到 24 小时内 100% 做得完的范围，然后在文档里主动说「我们刻意把 MVP 压到三个功能」——这句话本身就是加分项。功能列表超过 5 条，或文档里出现「平台」「生态」「操作系统」这三个词，就是在给评委发「这队会翻车」的信号。

9/9 → 9/27 行动清单

今天 · 9月9日 · 直播当晚

只做三件事

  • 听直播时专抓三样：预赛模板字段、SDK 获取方式与 license 申请流程、每队能拿几台设备。
  • 直播后立刻在群里问三个问题（按优先级）：① SDK license（token / licenseJson / license_signature）怎么申请、什么时候能拿到——没有 license 连不上真机，这是头号阻塞项；② 重点标记在 SDK 里是实时事件回调还是文件元数据；③ 是否提供实时音频流、每队几台设备。
  • 不要今晚就开始写文档。先拿到模板。
第一周 · 9/10 – 9/15

定人、定题、拿设备

  • 9/11 前把四个人的角色钉死：谁做 Android、谁做信号处理、谁做硬件结构、谁做路演。缺 Android 原生是最大缺口。
  • 申请 SDK + 领设备，走完 license 流程。
  • 把 SoundcoreSDKDemo 跑起来。就算没 license 连不上真机，也要把工程编译通过、六组能力的类名和回调结构读一遍。
  • 读社区实现理解协议——只读不抄，注意许可证陷阱。
  • 做 5 个真实用户访谈（车间管理员 / 设备维修工，30 分钟一个）。只有这一周有时间做。
第二周 · 9/16 – 9/22 · 生死线

技术穿刺，用真设备验证而不是推理

  • 【最高优先级】音频通路实测：设备录一段风扇声 → SDK 拉出来 → 看频谱。判断标准：正常态与异常态的梅尔谱距离是否可分。这条不通，当场换方向一，不要拖到 10 月。
  • 重点标记实测：录音中双击三次，拉文件看有无 marker 元数据；同时挂所有回调看有无实时事件。都不通则降级为「App 端按钮模拟」，并在文档里诚实写明。
  • Wi-Fi SoftAP 快传实测：测传输耗时和切热点后断网时长——决定你路演时敢承诺几秒响应。
  • Walking skeleton：手机麦克风 → 特征 → 阈值 → 插座断电，端到端跑通一次。这步完全不依赖录音豆，先证明下游管线是通的，10/16 那天只剩「把输入源换成豆子」一件事。
第三周 · 9/23 – 9/27

写文档，砍承诺

  • 9/23–24 写完初稿，数据流图先画、文字后填。
  • 9/25 承诺瘦身：逐条问「这条功能，10/16 到 10/17 之间四个人 100% 做得完吗？」做不完的删掉，不是标为「如时间允许」。
  • 9/26 外部评审：找一个不了解项目的工程师朋友，只给文档，让他复述「这东西是干什么的」。复述不出来 = 选题明确度不及格，回去重写第一句话。
  • 9/27 白天提交，不要拖到 23:59。顺便列决赛物料清单（磁吸托架、灯条、智能插座、热敏打印机、备用手机、充电宝、演示用的那台机器），10 月初就该到货。
2026-09-10 更新：并入 9/9「命题解析夜」的飞书智能纪要（20:00–22:00，653 人参会，WaytoAGI 承办）。纪要由 AI 生成，其中「边录边传」与「3+2 路演时长」两条与官方书面材料冲突，已在正文标注存疑，须向主办方核实。
